# Instruções Corrigidas para Geração de Páginas HTML de Correção de Questões de Residência Médica
## com Integração do Histórico de Provas Anteriores

## Objetivo

Gerar páginas HTML **exatamente idênticas** ao template fornecido no arquivo "TAMPLATE RESOLUTOR DE QUESTÕES.html", garantindo que todas as funcionalidades funcionem corretamente e a aparência seja perfeita. **Além disso, a correção deve ser personalizada com base no histórico do tema nas provas anteriores**, para mapear como a banca cobra aquele tema ao longo dos anos e antecipar variações.

---

## Arquivos e Dados de Entrada

Para cada correção, o LLM recebe:

1. **Anexos (apenas na primeira mensagem de cada conversa):** este Comando e o **Template HTML** (`TAMPLATE RESOLUTOR DE QUESTÕES.html`), cuja estrutura é fixa.
2. **Na própria mensagem (texto colado, não anexo):**
   - **A questão atual**, sob `--- QUESTÃO N ---`: enunciado completo e alternativas, precedidos pelo **Gabarito oficial** (e, quando existir, pela disciplina).
   - **O histórico de provas anteriores**, sob `--- PROVAS ANTERIORES RELEVANTES (pré-filtradas) ---`: as questões do acervo mais parecidas com a questão atual, cada uma com ano, número, gabarito e texto completo.

**Não há arquivo de perguntas nem arquivo de provas anteriores anexado.** O histórico completo **não é enviado**: o bloco inline já é o recorte relevante, escolhido por similaridade de termos. A única exceção é a questão que depende de figura/imagem: nela a mensagem pode trazer o `perguntas.pdf` anexado, usado **somente para ver a imagem** (o texto oficial continua sendo o colado na mensagem).

**Regras de uso desses dados:**

- O **Gabarito oficial** informado na mensagem é a fonte do `correctAnswer`. Use exatamente essa letra. Se a mensagem disser que o gabarito não está disponível, determine a alternativa correta pela melhor evidência clínica e deixe a justificativa muito explícita.
- O bloco **PROVAS ANTERIORES RELEVANTES** é a **fonte exclusiva** da seção 2.10 e a fonte do histórico citado nas seções 2.2, 2.3, 2.4 e 2.7. Não use memória, não cite questões que não estejam no bloco e não invente ano, número, enunciado ou gabarito.
- O bloco é um **recorte por similaridade**, não a lista exaustiva do acervo: algumas questões podem não tratar do mesmo tema. **Descarte** as irrelevantes e **não as cite**.
- Se a mensagem indicar que a questão contém imagem não disponível em texto, não invente o conteúdo da imagem.

## Passo a Passo para Geração

### 1. **Estrutura Exata do HTML**

- Utilize **exatamente** a estrutura do template fornecido, **sem qualquer adição ou modificação**:
  - Nenhum código extra (como "```html" ou outros caracteres)
  - Nenhum comentário adicional no HTML
  - Apenas o HTML puro conforme o template

### 2. **Substituição Exata dos Placeholders**

Substitua cada placeholder **exatamente** conforme especificado:

| Placeholder | Localização | Valor |
|-------------|-------------|-------|
| `[Theme]` | Dentro da div `.theme` | Tema da questão (ex: "Atenção Primária à Saúde: Atributos Essenciais") |
| `[QuestionNumber]` | Dentro do `<h1>` e da div `.question-number` | Número da questão (ex: "1") |
| `[QuestionText]` | Dentro da div `.question-text` | Texto completo da questão |
| `[DataTableSection]` | Após `.question-text` | Tabela HTML se houver dados tabulares |
| `[StatementsSection]` | Após `.DataTableSection` | Lista de afirmativas se houver |
| `[OptionsSection]` | Dentro da div `.options` | Estrutura exata das opções (veja abaixo) |
| `[CorrectAnswer]` | Dentro do script JavaScript | Letra da alternativa correta (ex: `'A'`) |
| `[CorrectionDetails]` | Dentro da div `.explanation` com ID `correctionContent` | Conteúdo completo da correção **personalizado com dados do histórico de provas** (veja detalhes abaixo) |

#### Formatação Exata para `[OptionsSection]`:

```html
<div class="option" onclick="selectOption('A')">
  <input type="radio" name="answer" id="optionA" value="A">
  <label for="optionA"><strong>A</strong> - Texto da alternativa A</label>
</div>
<div class="option" onclick="selectOption('B')">
  <input type="radio" name="answer" id="optionB" value="B">
  <label for="optionB"><strong>B</strong> - Texto da alternativa B</label>
</div>
<!-- Repetir para todas as alternativas (A a E) -->
```

### 3. **Configuração do Script JavaScript**

Mantenha **exatamente** o código JavaScript do template:

```javascript
let selectedOption = null;
const correctAnswer = '[CorrectAnswer]';

function selectOption(option) {
    const options = document.querySelectorAll('.option');
    options.forEach(opt => opt.classList.remove('selected'));
    const selected = document.querySelector(`.option input[value="${option}"]`).parentElement;
    selected.classList.add('selected');
    selectedOption = option;
}

function checkAnswer() {
    if (!selectedOption) {
        alert('Por favor, selecione uma opção antes de confirmar.');
        return;
    }
    const submitBtn = document.getElementById('submitBtn');
    const viewCorrectionBtn = document.getElementById('viewCorrectionBtn');
    document.getElementById('correctAnswer').textContent = `Alternativa ${correctAnswer}`;
    document.getElementById('userAnswer').textContent = `Alternativa ${selectedOption}`;
    const resultContainer = document.getElementById('resultContainer');
    resultContainer.style.display = 'block';
    if (selectedOption === correctAnswer) {
        submitBtn.textContent = 'Resposta Correta!';
        submitBtn.classList.add('correct');
        viewCorrectionBtn.style.display = 'inline-block';
        viewCorrectionBtn.textContent = 'Visualizar Correção Completa';
    } else {
        submitBtn.textContent = 'Confirmar Resposta';
        submitBtn.classList.remove('correct');
        viewCorrectionBtn.style.display = 'inline-block';
        viewCorrectionBtn.textContent = 'Visualizar Correção Completa';
    }
    resultContainer.scrollIntoView({ behavior: 'smooth', block: 'start' });
}

function showCorrection() {
    const correctionContent = document.getElementById('correctionContent');
    const viewCorrectionBtn = document.getElementById('viewCorrectionBtn');
    if (correctionContent.style.display === 'none' || correctionContent.style.display === '') {
        correctionContent.style.display = 'block';
        viewCorrectionBtn.textContent = 'Ocultar Correção Completa';
    } else {
        correctionContent.style.display = 'none';
        viewCorrectionBtn.textContent = 'Visualizar Correção Completa';
    }
}

function resetQuiz() {
    selectedOption = null;
    const options = document.querySelectorAll('.option');
    options.forEach(opt => opt.classList.remove('selected'));
    const radios = document.querySelectorAll('input[name="answer"]');
    radios.forEach(radio => radio.checked = false);
    const submitBtn = document.getElementById('submitBtn');
    submitBtn.textContent = 'Confirmar Resposta';
    submitBtn.classList.remove('correct');
    document.getElementById('viewCorrectionBtn').style.display = 'none';
    document.getElementById('resultContainer').style.display = 'none';
    window.scrollTo({ top: 0, behavior: 'smooth' });
}
```

### 5. **Conteúdo Completo da Correção com Integração dos Dados do Histórico de Provas**

O `[CorrectionDetails]` **deve incluir TODAS as seções abaixo (2.1 a 2.15)**, **utilizando obrigatoriamente as informações do bloco PROVAS ANTERIORES RELEVANTES fornecido na mensagem**. Para cada unidade de conhecimento da questão, identifique:

- **Das provas anteriores:** todas as questões **do bloco PROVAS ANTERIORES RELEVANTES** que abordaram o mesmo tema, com enunciado resumido, abordagem cobrada (diagnóstico, tratamento, complicação, conduta inicial, etc.), resposta correta (use o gabarito do rótulo de cada questão) e relação com a questão atual.

Se a questão foi errada, aponte explicitamente quais conceitos não foram cobrados nas provas anteriores (lacunas que podem ser exploradas na próxima prova).

### 6. **Instruções Específicas para Uso do Histórico de Provas Anteriores (bloco inline)**

O histórico chega **dentro da mensagem**, no bloco `--- PROVAS ANTERIORES RELEVANTES (pré-filtradas) ---`. O cabeçalho do bloco informa o acervo consultado (número de provas, intervalo de anos e total de questões) e o tamanho do recorte. Cada questão vem rotulada como `[ANO Qnúmero | Gabarito: letra | similaridade]`, ordenada da mais para a menos parecida.

**Para gerar a seção 2.10 (Histórico do Tema nas Provas Anteriores), o LLM deve:**

1. Ler as questões do bloco e **manter apenas as que abordam o mesmo tema** da questão atual.
2. Extrair de cada questão mantida o enunciado resumido, a abordagem cobrada (diagnóstico, tratamento, complicação, conduta inicial, etc.) e a resposta correta (letra do rótulo `Gabarito`; se constar "anulada/não informado", escrever isso).
3. Comparar a abordagem da questão atual com as anteriores, identificando o que mudou e o que se manteve.
4. Identificar qual abordagem **ainda não foi cobrada** entre as questões do bloco e que poderia aparecer na próxima prova.
5. Cruzar com os conceitos da questão atual para verificar se o histórico está coberto e sugerir revisão para as lacunas.
6. Se **nenhuma** questão do bloco tratar do tema (ou se o bloco informar que nenhuma atingiu o limiar), escrever: **"Tema não identificado nas provas anteriores do acervo consultado (intervalo de anos informado no cabeçalho do bloco). Isso sugere que pode ser um tema novo ou de baixa incidência, mas que merece atenção pela relevância clínica."** Como o bloco é um recorte, **não afirme que o tema nunca foi cobrado**.
7. **Não** cite a própria questão atual como "prova anterior" e **não** cite questões, anos ou gabaritos que não estejam no bloco.

### 7. **Validação Estrita**

Antes de salvar o arquivo, verifique **exatamente**:

1. **Nenhum caractere extra**:
   - Não deve haver "```html" ou qualquer outro texto além do HTML puro.
   - Verificar que o arquivo começa com `<!DOCTYPE html>` e não tem caracteres antes disso.

2. **Gradient contínuo**:
   - `html` deve ter `height: 100%`
   - `body` deve ter `min-height: 100%` e o mesmo background.

3. **Scroll correto**:
   - `resultContainer.scrollIntoView({ behavior: 'smooth', block: 'start' })` deve estar configurado para levar ao topo do resultado.

4. **Seções completas**:
   - Todas as seções de 2.1 a 2.15 devem estar presentes no `[CorrectionDetails]`.
   - Nenhuma seção omitida.

5. **Estrutura exata**:
   - Todas as classes, IDs e elementos devem ser idênticos ao template.
   - Nenhuma modificação no CSS ou JavaScript.

6. **Integração do histórico inline**:
   - A seção 2.10 deve conter obrigatoriamente a análise das questões do bloco PROVAS ANTERIORES RELEVANTES.
   - Se nenhuma questão do bloco tratar do tema, usar a frase prevista na seção 6 e sugerir a inclusão do tema no estudo.
   - `correctAnswer` deve ser a letra do **Gabarito oficial** informado na mensagem.

- **Escapar caracteres especiais**:
  - `&` → `&amp;`
  - `<` → `&lt;`
  - `>` → `&gt;`
  - `"` → `&quot;`
  - `'` → `&#39;`

- **Imagens**:
